# 工具访问边界

## 终端工具配置

终端工具默认关闭，不会注册到 Manus 和恋爱助手共用的工具集合。确需在可信的本地环境使用时，可通过配置 `app.tools.terminal.enabled=true` 或环境变量 `APP_TOOLS_TERMINAL_ENABLED=true` 显式启用，重启应用后生效。

启用后，模型可以以应用进程的权限执行终端命令；该开关本身不提供身份认证、命令限制或运行环境隔离。仅在可信环境中启用，并为运行进程配置适当的隔离和权限。

`ToolRegistrationTest` 是离线测试，只检查工具是否注册，不执行终端命令，也不调用模型或外部服务。

## 文件工具：只接受文件名

文件读写、资源下载、PDF 生成共用 `ToolFileAccess` 校验。模型只能传入 `笔记.txt`、`报告.pdf` 这样的普通文件名，不能传相对路径、绝对路径、盘符、网络共享路径、Windows 设备名或备用数据流名称。例如 `../secret.txt`、`C:\secret.txt`、`NUL.txt`、`file.txt:stream` 都会被拒绝。

三个工具继续使用各自的固定目录：

| 工具 | 目录（相对项目运行目录） | 限制 |
| --- | --- | --- |
| 文件读写 | `tmp/file/` | UTF-8 文本；读取最大 1 MiB |
| 资源下载 | `tmp/download/` | 最大 10 MiB |
| PDF 生成 | `tmp/pdf/` | 仅接受普通文件名 |

目录、上层目录和目标文件不能是符号链接或 Windows junction（目录连接）。写入先完成临时文件，再替换目标；下载失败、超限或 PDF 生成失败时保留原文件。错误结果不回传底层异常、远端响应正文或内部堆栈。

这些检查针对工具参数及已存在的符号链接、目录连接。应用的工作目录应只允许可信进程修改；路径检查本身不是操作系统沙箱，不能保证抵御同机进程在检查与实际读写之间并发替换目录，也不能识别被其他进程预置为普通文件的硬链接。需要通过运行账户、目录权限和部署隔离防止这类本机修改。也没有新增用户隔离，同一应用仍共用上述目录。

## 网络工具：只允许公网 HTTP/HTTPS

网页抓取与资源下载共用 `SafeHttpClient`：

- 只接受 HTTP/HTTPS，不接受 `file:`、FTP 或带用户名/密码的 URL。
- 在发请求前解析域名，全部解析地址都必须通过公网检查；拒绝本机、内网、链路本地、组播及特殊保留地址，覆盖 IPv4 和 IPv6。
- 连接使用同一份已校验的解析结果，避免再次解析后连到不同地址；HTTPS 仍按原域名校验证书。
- 关闭自动重定向，每一次跳转重新检查协议、主机和地址；最多跳转 5 次。
- 不读取系统代理，不自动重试，不保存 Cookie。
- 连接/读取等待最多 10 秒，域名解析、HTTP 请求及跳转共享 30 秒预算。系统 DNS 不一定能被中断，因此解析使用有界后台线程池，超时后调用方返回错误；无法中断的底层解析最多占用 2 个后台线程，不会无限创建线程。
- 网页响应最大 2 MiB，下载最大 10 MiB；未知长度和解压后的响应也受限。网页正文仍按原规则最多保留 10000 个 Unicode 码点并标记截断。

因此，直接抓取本机开发服务或内网站点现在会失败。这是默认访问策略，没有提供配置开关来绕过。离线测试通过包内构造器注入假 DNS 和本地 HTTP 服务，实际应用的默认构造器始终启用公网限制。

## 离线验证

`FileOperationToolTest` 和 `ToolFileAccessTest` 验证正常读写、路径穿越、设备名、目录链接和失败时文件保留；Windows 下链接用例只在测试临时目录中创建 junction，其他系统使用符号链接。

`SafeHttpClientTest`、`WebScrapingToolTest` 和 `ResourceDownloadToolTest` 验证公网地址判断、固定 DNS 结果、危险重定向、响应超限、超时、字符编码和下载文件保留。`ResourceDownloadToolTest` 已从真实外网下载改为本地假服务，现属于可随时运行的离线测试。
